# MAIN-R1：独立自适应 Paper 实验

MAIN-R1 使用动态真实行情，在 MAIN、MAIN 加含费价格 0.60 下限、FAST、PLUS 四个候选之间选择，也可以选择空仓。对外只有一个组合账本。四个独立影子账户持续积累未来选择需要的数据，影子账户的资金和收益不能与组合相加。

这项实现只开放 Paper。它不读取签名凭据，不调用钱包、签名、提交、撤单或赎回 API，不改变现有 MAIN、FAST、PLUS、paired trials 或实盘配置。新增代码不会被旧的默认启动入口自动运行。

## 账本和行为

每个钱包初始虚拟资金为 $1,000，分别保存在：

| 路径（相对独立数据目录） | 用途 |
| --- | --- |
| `portfolio/paper.sqlite3` | 唯一 MAIN-R1 组合结果 |
| `shadows/MAIN/paper.sqlite3` | MAIN 入场信号 |
| `shadows/MAIN_FLOOR_060/paper.sqlite3` | MAIN 信号，加最终同帧含费扫档价格下限 0.60 |
| `shadows/FAST/paper.sqlite3` | FAST 入场信号 |
| `shadows/PLUS/paper.sqlite3` | PLUS 入场信号 |

候选继承的是原策略的**入场信号**，不是原策略的完整执行规则或历史收益。所有钱包统一使用每轮最多一次正成交、同一风险模板、持有至官方结算的研究规则。价格下限不合格仅跳过当前帧；同一轮尚未有正成交时可以等待后续帧。任何部分成交都会永久锁定整轮，不能换方向补单。

选择器只使用在决策时已可得的真实参考价与完整、已官方结算的共同影子样本。冷启动或证据不足时组合空仓，影子账户继续记录。一次市场选择固定后，不根据随后才看到的胜负换到本轮赢家。没有根据模型分数加大仓位的机制。

新市场刚出现但双侧盘口尚未到齐时，系统只等待。到达继承的最早入场窗口、参考源已验证、涨跌双侧盘口及深度均新鲜后，才作本轮首次共同选择；不会把开局短暂的空盘口永久锁成整轮空仓。已经作出的空仓选择仍保持固定。确认和官方结算不受这一入场等待影响。

原 MAIN 信号基准必须作为完整白名单快照显式提供，开始实验后写入 `campaign.json` 并冻结。配置变化需要一个明确的新实验目录；重启不能改参数、重置历史峰值或清除暂停。示例 JSON 的数值来自已审阅源码的参考默认值，**不是服务器当前生效参数的证明**。

`campaign.json` 还冻结启动时实际源文件的 SHA-256 与安装依赖版本，包括全部 `main_r1_*` Python 模块、MAIN/FAST/PLUS 信号、执行、存储、行情和公共客户端等明确白名单，以及 Python/SQLite 版本。JSON 中填写的 `source_commit` 只是人工提供的基准来源，不能充当执行代码证明。配置 ID 同时绑定这些内容，`/api/status` 可查看 `runtime` 指纹。

即使只是修改新的状态页，运行代码指纹也会变化，旧实验目录会明确拒绝启动新版本。升级前先使用原版本处理旧账本的未结订单、未知状态与仓位对账，再为新研究使用新目录；不得把删账本、复制残缺账本或清零余额当作升级步骤。程序在打开已有数据库为可写之前，会先只读核验该钱包的独立策略标识和初始资金，拒绝外来数据库、符号链接与硬链接。

选择器使用过去 300 秒已收到的参考价分类：需要至少 30 个点、至少 270 秒覆盖、最大 30 秒间隙，并检查双侧盘口的新鲜度、价差和邻近深度。完整样本按趋势、区间、高波动或中性状态积累，证据不足便空仓。评分采用向零收缩的均值、时间块误差惩罚和每份额外 0.01 成本压力；换臂还需要持续改善证据与最短持有周期。这些都是冻结的 Paper 研究假设，不是已经验证的统计置信保证或历史最优参数；完整常量记录在 `campaign.json` 的 `selector_config`。

## 研究风险模板

每个虚拟钱包各自计算以下上限，不与其他影子钱包或已有生产账户合并：

- 单笔最大总预算为 `min(5, 0.005 × 已对账保守 NAV, 可用现金, 全局剩余风险额度)`。
- 未决原始含费成本与预留现金合计不超过该钱包 NAV 的 1%，最多两个未决市场轮次。
- 当前订单精度或最小份额不满足时跳过，不为了满足最小订单加大风险。
- 北京时间自然日，经外部资金流调整后的 NAV 损失达到 2% 暂停到次日；其他暂停原因仍保持。
- 历史峰值回撤达到 8% 持久暂停，等待明确复核；日切和重启不清除此状态。
- 未知订单、估值不足或实际成交低于 0.60 预估门槛等异常保留真实记录并阻断新风险，已有订单和仓位继续确认、结算。

NAV 使用一致会计检查点：自由现金、仍拥有的预留现金、已确认未结算仓位按可执行买盘扣费估值，以及已核实的待释放兑付只各计一次。未释放兑付不作为可下单现金。缺失、陈旧或深度不足的估值不能用零或成本价偷偷补齐。

这些是未经完整可执行回放的保守 Paper 研究参数，不是收益保证或真实资金配置建议。暂停阈值不是最终损失的硬封顶。

模拟继续采用 `realistic-paper-v1`：至少 1 秒到达延迟，到达时使用可见深度的 50%，12 秒确认、60 秒兑付延迟，最多 2 秒轮询迟到。它们是模拟假设，不是交易所承诺。FAK 的买入限价只能约束上限；更优价格或部分成交仍可能使实际含费成本低于 0.60。此时保留成交、锁定轮次并暂停新风险，不自动反向卖出。

### 本次成交边界修复

- R1 的 `MAIN`、`MAIN_FLOOR_060` 候选先把买入上限收紧到满足已配置最小净优势的合法价格档位，再按最终同帧盘口、实际预算和逐档舍入费用复核 `信号分数 − 含费报价均价`。不足时记录 `EDGE_WAIT`，不预留资金。FAST、PLUS 保留各自的入场限价逻辑，原有策略默认入口与参数不变。
- 费用已包含在扫档结果的 `cash`、成交成本与净收益中，只入账一次。到达时若极小部分成交因费用舍入低于净优势门槛，保留全部正成交与真实模拟成本，锁定整轮，并以 `net_edge_drift` 暂停新风险；已有成交继续确认及官方结算，不删除不利样本。
- 预计到达时刻固定为 `submitted_at + arrival_delay`，截止时刻为该时刻加冻结的最大轮询迟到量，当前为 2 秒。盘口源时间和接收时间均不得早于预计到达时刻；窗口内只有较早的有效盘口时记录 `ARRIVAL_WAIT`，不修改 `due_at` 或顺延截止时刻。超时或无法核实的到达证据进入 `UNKNOWN` 并保留预算，只有已核实到达盘口的限价内零成交才释放预留。
- 仅 R1 显式开启严格 WS 接收时间：保留底层 socket 读取时记录的 `received_ms`，不以稍后的解析或发布时刻刷新盘口；无效接收时间拒绝发布。WS 缺少的价格精度和最小份数只从新鲜、代币与价格精度匹配的公共规则补齐。其他 `TrialFeed` 和盘口采集器默认行为保持不变。

## 准备配置

复制 `deploy/main-r1-paper/main-r1.example.json` 为同目录的 `main-r1.json`，逐项核对当前 MAIN 的白名单入场参数，并更新 `provenance` 的采集时间、源码版本和来源说明。不得把 `.env`、钱包、API 凭据或整个运行配置复制到这里。JSON 不接受未知字段或任何开启实盘的开关。

当前同源行情接口支持已审阅 MAIN 的 `BASE`、`MIXED`、`NONE` 三个模式值；其他模式会明确报错。配置不会因为环境里存在同名参数而变化。

## 本机运行

使用 Python 3.11 以上以及仓库声明的依赖。在仓库根目录运行：

```bash
python -m polybot2other.main_r1_paper \
  --config deploy/main-r1-paper/main-r1.json \
  --source /path/to/existing/market-data \
  --data-dir /path/to/independent/main-r1-data \
  --host 127.0.0.1 --port 8794
```

安装本项目后也可以使用 `polybot2other-main-r1-paper`，参数相同。新数据目录必须为空；后续启动复用同一目录和同一配置。第二个写进程会被独占锁拒绝。来源目录和输出目录不能重叠。

来源目录必须包含运行中市场采集器提供的 `polybot2other-real-btc.sqlite3` 和 `live-accounts/market.references.sqlite3`。两个数据库都以 SQLite `mode=ro`、`query_only` 打开；不创建缺失来源文件、不 checkpoint、不复制为静态数据库，不使用 `immutable` 忽略实时 WAL。市场、参考价或盘口陈旧时等待，不捏造行情。

公共市场费率、价格精度等元数据由五个钱包共用受锁保护的短缓存，最长 5 秒后强制重新读取，不整轮沿用旧参数。读取失败时不回退旧费率或旧价格精度；共享短暂失败等待可避免多个钱包同时重复请求。

本机页面：`http://127.0.0.1:8794/`；JSON 状态：`/api/status`；进程健康：`/health`。全部只读，只允许回环监听，不提供改资金、改参数、清空暂停、下单或删除记录接口。健康接口里的 `feed_ready` 与进程存活分别报告，行情等待或风控暂停不应触发“清空状态再重启”。

## 独立 Docker 模板

模板仅在 Linux 的 host 网络模式下启动新服务，端口 8794 不占用原面板端口。启动之前应先完成配置核对，并准备独立数据目录给 UID/GID 10001 写入。

```bash
docker compose -f deploy/main-r1-paper/compose.yaml config
docker compose -f deploy/main-r1-paper/compose.yaml build main-r1
docker compose -f deploy/main-r1-paper/compose.yaml up -d --no-deps main-r1
```

可通过 `MAIN_R1_CONFIG_PATH`、`MAIN_R1_DATA_DIR`、`EDGEPULSE_SOURCE_DATA_DIR` 显式指定主机路径。模板逐文件只读挂载两个市场数据库及各自的 `-wal`、`-shm`，不暴露 `accounts.sqlite3`、`.env` 或整个生产数据目录。所有来源绑定都使用 `create_host_path: false`；缺文件时明确启动失败，不偷偷创建空目录。

运行中的 WAL 数据库需要对应 sidecar 文件已存在且 UID 10001 可读。数据库或 sidecar 被源服务替换 inode 后，应停止并重建**这个新服务**的文件挂载以连接新文件；不能改成 `immutable` 或复制旧文件来掩盖问题。源采集器或已验证参考价停止后，新系统会等待输入，已有记录保留。

仓库内旧部署文件没有被修改。以上命令是供审核后显式启动的模板，本次代码交付不会执行这些命令或替用户启动服务器。

## 升级已有 MAIN-R1 实验

本次修复会改变运行代码指纹，**必须新建实验目录**；旧 `campaign.json`、组合与四个影子账本保留为旧版本证据，不复制进新目录。以下操作由部署者在自己的主机执行。

1. 先保留旧配置、旧代码和依赖环境；Docker 部署还应保留实际运行的旧镜像，不能假定重新构建同一 Git 提交就会得到相同依赖。使用旧版本处理已有确认、官方结算和延迟兑付。检查 `http://127.0.0.1:8794/api/status` 的 `portfolio` 及全部 `shadows`：`execution.counts` 中 `IN_FLIGHT`、`CONFIRMING`、`UNKNOWN` 均为零，`open_cost` 与 `execution.pending_settlement_cash` 均为零，并核对没有孤立未决订单或其他对账异常。
2. 旧版没有停止新入场但继续结算的维护命令，网页也是只读的；停止进程会同时停止确认和结算。完成上述检查后正常停止旧 MAIN-R1；Docker 在原配置及原路径环境下执行 `docker compose -f deploy/main-r1-paper/compose.yaml stop main-r1`，本机前台进程使用 Ctrl-C。停止后只读复核旧账本。若停止期间仍留下未决，使用保留的旧运行环境继续处理；缺少到达证据的订单重启后可能进入持久 `UNKNOWN`，需要保留证据单独复核，不能用重启、手改数据库或清空暂停把它当作已解决。不要停止提供市场数据的原采集服务。
3. 更新到本次修复后的 `dev` 提交，核对独立 `main-r1.json`，为新实验选择从未使用的空目录。Docker 使用下面的路径示例；先把路径改为本机实际值，来源数据库及其 WAL/SHM 仍须满足上一节的只读挂载条件。

```bash
export MAIN_R1_CONFIG_PATH="$PWD/deploy/main-r1-paper/main-r1.json"
export EDGEPULSE_SOURCE_DATA_DIR=/opt/edgepulse/data
export MAIN_R1_DATA_DIR=/opt/edgepulse/main-r1/runs/upgrade-20261124-01
sudo install -d -m 0700 -o 10001 -g 10001 "$MAIN_R1_DATA_DIR"
docker compose -f deploy/main-r1-paper/compose.yaml config
docker compose -f deploy/main-r1-paper/compose.yaml build main-r1
docker compose -f deploy/main-r1-paper/compose.yaml up -d --no-deps --force-recreate main-r1
```

4. 检查 `http://127.0.0.1:8794/health` 与 `/api/status`：`mode` 为 `PAPER_ONLY`，`live_enabled` 为 `false`，新 `config_id`、`runtime`、`start_at` 与新目录的 `campaign.json` 一致。组合与影子均从各自 1,000 虚拟资金开始，新的共同样本重新积累；`waiting_start`、`waiting_data` 或证据不足而空仓不等于启动失败。旧实验收益与新实验收益分开报告。

本机 Python 启动同样使用新 `--data-dir`，其余参数仍按“本机运行”一节，监听地址和端口保持 `127.0.0.1:8794`。同一实验的正常重启才复用原目录、原配置和完全相同的运行指纹；切换版本后不要把旧目录作为重试目标。

## 验证与当前边界

离线单元测试和集成测试覆盖配置冻结、独立账本、只读来源、无实盘入口、行情与预算绑定、整轮锁、恢复、风险停机和选择的时间边界。测试使用本地合成账本与假行情，不访问生产交易接口。

这次实现不等于已经完成未来 14 天、500 笔等预先定义的观察门槛，也不是完整执行历史回测。公开盘口不能证明隐藏流动性、排队优先级或真实链上竞争。已有 shadow 或组合账本不能事后删除失败记录、临时改参数，再把剩余结果当作样本外证据。
