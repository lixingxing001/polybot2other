# 双翼配对 V2

V2 是独立 Paper 试验，不需要事先训练。V1 的 `$100 → $86.996530` 和50个有成交市场完整保留，停止新增，作为历史对照；不是给旧账本重置资金或改写亏损。原四策略、衡准和实盘开关保持原设置。

## 这次修复的边界

| V1 问题 | V2 行为 |
|---|---|
| 已亏约$9.17还允许新开$5一组，未计在途和持仓 | 下单事务内预留全部委托资金和最大损失；未确认买入、待确认卖出、未配对持仓均占风险额度 |
| 盈利与损失相抵后可重复消耗亏损额度 | 24小时内负损益单独累计，盈利不抵扣；每次新订单还检查本轮剩余损失空间 |
| Gamma规则刷新失败会连已有持仓退出一起阻断 | 新开仓元数据与退出条件分开；退出线程独立核对CLOB资产、当前费用和买盘，不依赖Gamma页面 |
| 等全部成交确认后才处理，退出失败15秒后才试 | 已确认的可用部分可单独退出；2秒后重试，严重亏损或失败后允许以最小tick为卖出限价，仍按实际到达深度成交 |
| 保守穿价假设与成交带结果混在同一收益里 | 两个独立$100账本：TAPE按成交事件模拟，STRESS另外包含穿价模型；所有结果同时展示，不能相加或择优隐藏 |
| 报价跨度大、12秒不动的报价容易滞后 | 更窄的均衡价带、短时平稳性检查、双侧退价、4秒有效期，盘口明显移动会更早撤单 |

仍有不能消除的限制：没有有效买盘就不能凭空卖出；已确认残余低于真实最小量或数量精度时必须保留至终局。$0.40是紧急退出的触发条件，不是保证成交价或单笔最大亏损。

## 风险预算

新增前必须同时满足：

1. 24小时已实现负损益总额＋当前最大未决损失＋新委托预算 ≤ 日额度（默认$10）。
2. 本轮相对初始本金的已实现净亏损＋当前最大未决损失＋新委托预算 ≤ 本轮额度（默认$10）。
3. 模拟现金扣除其他委托预占后足以承担本次预算。

已经付费、已确认且等量的互补份额才允许抵扣风险。未确认配对不提前释放风险；卖出已撮合未确认期间，原成本继续占用风险。预算改变、暂停/恢复、跨日和重启不会清掉本轮损失。

因此剩余空间小于下一组完整预算时，即使尚未实际亏满$10也不会再开这一组；界面会直接显示可新增空间和所需预算。用户主动降低额度至已承诺风险以下时，旧承诺不能瞬间消失，系统撤回未成交买单并继续管理已有份额。

## 冻结的初始试验参数

| 项目 | V2默认值 |
|---|---|
| 主 / 压力本金 | 各自$100，不合并 |
| 每组双边总预算 | $5，页面可调 |
| 并行市场上限 | 5，同时受风险预算限制 |
| 开仓时段 | 开盘30秒后，剩余至少120秒 |
| 报价范围 | 双侧均为$0.30–$0.70 |
| 盘口要求 | 源年龄≤1500ms、接收年龄≤1000ms、跨侧时间差≤500ms |
| 短时观察 | 最近约4秒中至少2秒连续盘口，至少4个观察点；中间价区间不超过$0.02 |
| 报价与配对成本 | 每侧至少比买一低一个tick，总报价≤$0.96 |
| 单侧价差 | ≤$0.03 |
| 当前退出成本筛选 | 不高于$0.40且不高于预期配对毛差价的两倍；不是未来价格预测 |
| 报价有效期 / 单边等待 | 4秒 / 约2秒后进入管理 |
| 发送、撤单、确认、领取 | 2秒、2秒、12秒、60秒模拟假设 |
| 参与率 | 成交事件扣减队列后25%；主动到达深度25% |
| 退出费用证据有效期 | 独立CLOB核验15秒，盘口仍独立检查真实源/首次接收时间 |
| 紧急退出触发 | 估计单边损失≥$0.40，或第一次退出失败，或裸露持续≥15秒 |

这些是预先确定的研究参数，不是保证盈利的条件。没有为了让主账本盈利而删除压力账本的亏损；没有将旧历史或人工测试单导入V2账户。

## 独立退出通道

新开仓仍使用Gamma与CLOB的一致性核验。持仓退出另有公共HTTP线程，只读取CLOB市场和相关token的book。它校验condition、token映射、协议、交易状态、费用、tick和最小量；允许只有买盘的有效盘口用于卖出，不强制要求同侧仍有卖盘。

普通网络失败不会把最近核验过的退出条件删掉，但其原始有效期不会刷新。协议/资产/费用语义冲突立即使条件不可用，直到重新核验。新HTTP响应也不能把先收到的另一个盘口重新标成刚收到。显式空买盘会使旧买盘失效，不回退到更早的好价格。

已结算和无剩余份额的市场不持续拉取退出盘口。在内存中只保留当前及仍有风险的市场缓存，历史委托、成交、利润与证据都保留在SQLite。

## 两情景及同期对照

TAPE主账本仅按真实公开SELL事件模拟排队。STRESS使用同样的策略与风险规则，另计严格卖盘穿价的假设成交，独立重跑资金与持仓，不把主账本成交直接复制过去。两者模拟成交路径和资金占用可能不同。

界面同时显示两侧的已实现盈亏、压力净值、风险额度、实际模拟投入和完成市场数量。主账本盈利而压力亏损时会明确提示：不能据此宣称优化有效。

主账户优化版对照通过只读数据库获取，只统计V2启动之后新开仓且已完成的记录。原策略每笔金额可能不同（本次保留用户已保存的$10），所以同时报告投入和投入收益率，不比较不同起点的总利润。未完成持仓和不同执行假设仍需另外考虑。

## 操作与数据

- 运行入口仍是 `./start-macos.sh`，地址 `http://127.0.0.1:8791/#bot`。
- `data/paired-paper-v2/paper.sqlite3`：成交带主账本。
- `data/paired-paper-v2/stress.sqlite3`：独立穿价压力账本。
- V1原账本仍为 `data/paired-paper-v1/paper.sqlite3`，没有迁移或清空。
- `GET /api/paired-v2` 返回两情景、退出通道、风险预算和同期对照。
- `POST /api/paired-v2/settings` 使用本机同源及独立令牌，设置同时应用两情景；拒绝实盘字段。顶部Paper/BTC暂停也阻止V2新增，已有持仓继续管理。

启动环境默认 `POLYBOT2OTHER_PAIRED_V2_ENABLED=true`、`POLYBOT2OTHER_PAIRED_V1_FROZEN=true`。该模块只调用公共GET，不加载交易签名器，不提供真实买卖、合并或领取操作。

依据：[官方订单独立处理与库存管理](https://docs.polymarket.com/trading/market-making)、[官方订单最小量与精度](https://docs.polymarket.com/trading/place-orders)。现有公开资料不支持擅自把低于最小份额的残余当成已卖出。
