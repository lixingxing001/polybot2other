Market Scout 非 BTC 市场扫描到 Paper 下注流程

这份文档按当前代码实现写清楚市场页的完整链路：从 Gamma API 拉取非 BTC 活跃市场， 本地过滤和排序，CLOB 盘口增强，LLM 输出结构化判断，再经过 Paper 自动下注闸门和模拟成交写入独立账本。 重点是把每一道关口、每一个阈值、每个会阻止下注的条件讲清楚，方便你判断这套逻辑到底有没有在工作。

当前接入：候选扫描 当前接入：LLM 实时分析 当前接入：Paper 自动下注 Live 自动下注：锁定 外部新闻核验：未自动接入
1. 总览 2. 运行入口 3. 配置来源 4. 扫描市场 5. 本地过滤 6. 候选打分 7. 盘口增强 8. LLM 分析 9. 结果归一化 10. Paper 下注 11. 成交和账本 12. 页面和日志 13. 策略边界 14. 压力测试

1. 总览

严肃边界

当前 Market Scout 能做的是扫描、筛选、让 LLM 给出结构化建议、在 Paper 隔离账户里自动模拟下注。 它目前没有接入真钱 Live 自动下单，也没有自动浏览新闻源。任何“胜率保证”都不成立，只有可审计的闸门和日志。

1 启动扫描器

_start_market_scout() 启动后台线程，按市场页配置决定是否扫描。

2 拉取市场

从 Gamma API 拉活跃市场，按 24h 成交量倒序取样。

3 过滤候选

去掉 BTC、非二元、关闭、低流动性、低成交量、极端价格、宽价差市场。

4 盘口增强

对 top 候选补充 CLOB best bid、best ask、size 和 spread。

5 LLM 判断

只允许输出 JSON，决策只能是 RECOMMEND 或 NO_TRADE。

6 归一化

校验 slug、outcome、confidence、max entry、有效期和风险字段。

7 Paper 闸门

本地再次检查置信度、入场价、价差、持仓数、重复持仓、日亏损和现金。

8 模拟成交

使用 simulate_fak_buy() 按 FAK 限价模拟买入。

9 写入账本

订单和成交写入 Market 独立 Paper SQLite，和 BTC 账本隔离。

10 页面展示

候选、LLM 分析、推荐、Paper 账户、下注列表和 Terminal 日志持续刷新。

2. 运行入口

环节 代码位置 实际作用
扫描线程 src/polybot2other/bot.py，_start_market_scout() 如果全局 Market Scout 开关和页面扫描开关都打开，就启动 polybot2other-market-llm-scout 后台线程。

LLM 分析 _maybe_analyze_market_scout_candidates() 检查 LLM 开关、全局开关、API key、候选签名和 TTL，再决定是否发起 LLM 请求。

和 BTC 页面的关系

BTC 页面控制的是 BTC 数据采集、BTC websocket、BTC 策略 tick。Market Scout 由市场页自己的 scanner_enabled 控制。关闭 BTC 业务不会自动关闭 Market Scout，关闭市场页扫描开关才会停止非 BTC 市场扫描。

3. 配置来源

Market Scout 配置分两层：环境变量给首次启动默认值，市场页齿轮配置会保存为运行态 JSON。 页面保存后，后端会清洗数值范围，防止异常输入把扫描器或 Paper 账本搞坏。

配置 默认值 环境变量 用途和调参影响
market_scout_enabled true POLYBOT2OTHER_MARKET_SCOUT_ENABLED 非 BTC 扫描器总开关。关闭后市场页不会扫描。
scan_interval_seconds 30 POLYBOT2OTHER_MARKET_SCOUT_INTERVAL_SECONDS 扫描间隔，页面可调，后端允许范围是 5 到 3600 秒。越低越频繁，API 和 LLM 成本越高。
market_scout_scan_limit 120 POLYBOT2OTHER_MARKET_SCOUT_SCAN_LIMIT 每轮从 Gamma 拉取市场数量，后端夹在 20 到 500。
analyze_top_n 10 POLYBOT2OTHER_MARKET_SCOUT_ANALYZE_TOP_N 每轮送入 LLM 的候选数量，页面可调，后端范围 1 到 20。
market_scout_min_liquidity 5000 POLYBOT2OTHER_MARKET_SCOUT_MIN_LIQUIDITY 候选最低流动性。越高越稳，机会越少。
market_scout_min_volume_24h 1000 POLYBOT2OTHER_MARKET_SCOUT_MIN_VOLUME_24H 候选最低 24h 成交量。越高越偏向主流热门市场。
market_scout_llm_ttl_seconds 120 POLYBOT2OTHER_MARKET_SCOUT_LLM_TTL_SECONDS 同一组候选重复出现时，TTL 内不重复打 LLM，减少无意义请求。
market_scout_llm_timeout_seconds 8 POLYBOT2OTHER_MARKET_SCOUT_LLM_TIMEOUT_SECONDS LLM 分析超时。你之前调到 60 秒后，慢模型更容易返回，但单轮扫描等待也更久。
paper_initial_balance 100 POLYBOT2OTHER_MARKET_SCOUT_PAPER_INITIAL_BALANCE 市场页独立 Paper 初始资金，页面修改后会按差额修正账户现金。
paper_stake_dollars 2 POLYBOT2OTHER_MARKET_SCOUT_PAPER_STAKE_DOLLARS 单笔 Paper 预算，后端范围 0.1 到 10000。
paper_max_open_positions 3 POLYBOT2OTHER_MARKET_SCOUT_PAPER_MAX_OPEN_POSITIONS 最多同时持仓数量，后端范围 1 到 50。
paper_max_daily_loss 10 POLYBOT2OTHER_MARKET_SCOUT_PAPER_MAX_DAILY_LOSS 24 小时已实现亏损上限。触达后停止 Paper 自动下注。
min_confidence 0.72 POLYBOT2OTHER_MARKET_SCOUT_PAPER_MIN_CONFIDENCE LLM 推荐进入 Paper 执行前的最低置信度。
max_entry_price 0.65 POLYBOT2OTHER_MARKET_SCOUT_PAPER_MAX_ENTRY_PRICE 后端允许的最高买入价，还会和 LLM 给出的 max_entry_price 取更低值。
max_spread 0.04 POLYBOT2OTHER_MARKET_SCOUT_PAPER_MAX_SPREAD Paper 执行前允许的最大盘口价差。越小越少下单，越大越容易吃滑点。

4. 扫描市场

单轮扫描由 _run_market_scout_once() 执行。它调用 PolymarketClient.get_active_markets(limit=scan_limit, order="volume24hr", ascending=False)， 从 Gamma API 拉取活跃市场，优先覆盖最近 24 小时成交量较高的市场。

Gamma 参数 值 意义
closed false 只拉未关闭市场。
active true 只拉活跃市场。
archived false 排除归档市场。
order volume24hr 按 24 小时成交量排序。
ascending false 成交量从高到低。
limit 20..500 实际值来自配置，后端强制夹紧。

解析字段

每个 Gamma row 会进入 _market_scout_candidate_from_raw()，解析为内部候选对象。 这里会提取市场 slug、问题、事件标题、描述、outcomes、CLOB token ids、outcome prices、流动性、成交量、spread、best bid、best ask、结束时间和市场状态。

5. 本地过滤

本地过滤由 _market_scout_reject_reason() 执行。任何一条命中都会让该市场退出候选池， 过滤统计会写入 Market LLM Terminal，方便看清楚本轮机会少的根因。

过滤原因 触发条件 目的
btc_market slug、question、event_title、description 包含 btc 或 bitcoin 市场页专门做非 BTC，避免和 BTC 页面策略混在一起。
inactive 非 active，或 closed，或 archived 避免分析已经失效的市场。
orders_closed acceptingOrders 关闭，或 enableOrderBook 关闭 有市场但无可执行盘口时直接排除。
non_binary outcomes 数量或 token ids 数量不等于 2 当前执行和账本按二元市场设计，复杂多选市场先排除。
missing_prices 可用 outcome price 少于 2 个 缺价格时无法估算入场价和市场状态。
resolved_or_extreme_price 最高价大于等于 0.97，或最低价小于等于 0.03 排除基本已分出胜负或赔率极端的市场。
low_liquidity liquidity 低于 market_scout_min_liquidity 减少进入薄盘口市场的概率。
low_volume_24h 24h volume 低于 market_scout_min_volume_24h 过滤冷门市场，降低价格不连续风险。
wide_spread Gamma spread 存在且大于 0.08 先在候选阶段过滤明显宽价差。
机会少时先看过滤统计

如果终端里一直显示候选很少，先看 过滤统计 中是 low_liquidity、low_volume_24h、 wide_spread 还是 orders_closed 占比高。盲目调低所有阈值会让 Paper 下单变多，同时会把薄盘口和垃圾机会放进来。

6. 候选打分和排序

过滤后的市场先按 _market_scout_candidate_score() 计算基础分，再进入 Market Scout 选择画像。 基础分不代表胜率，它只是流动性、成交量、价格不确定性和价差的粗排序。

score = log1p(liquidity) * 0.35 + log1p(volume_24h) * 0.45 + uncertainty * 4.0 + (1.0 - spread_penalty) * 2.0 uncertainty = max(min(price, 1 - price)) spread_penalty = clamp(spread / 0.08, 0, 1)
流动性权重

流动性越高，理论上越容易进出，分数增加。使用 log1p 避免大市场把所有候选碾压。

24h 成交量权重

最近交易更活跃的市场优先送入 LLM，避免把模型预算浪费在死市场。

不确定性权重

价格接近 0.5 的市场 uncertainty 更高，说明仍有争议空间。太接近 0 或 1 的市场前面已经过滤。

新漏斗会额外计算 selection_score：事件驱动市场加分，体育盘降权，长期 outright 降权， 过期体育盘会被阻断，同主题和同事件优先只占一个 LLM 坑。页面展示前 20 个候选，真正送入 LLM 的数量由 analyze_top_n 控制，当前运行态是 10。

选择画像 处理方式 目的
event 地缘政治、宏观、监管、选举、战争、航运、官方公告类市场加分。 把更适合 LLM 做事件分析的市场送到前面。
sports 体育比赛、spread、O/U、按日期胜负市场降权。 减少同一场比赛和实时比分依赖市场长期占坑。
outright 世界杯冠军、长期冠军盘这类长周期 outright 降权。 降低长期叙事盘压住短期事件盘的概率。
stale_sports_market 结束时间已过的体育盘不送入 LLM。 避免 LLM 因赛况缺失反复返回 NO_TRADE。
同主题和同事件去重 第一轮同一个事件 slug 或同一个主题只占一个坑，不够时才放宽到两个。 防止同一市场族的不同到期日吃掉全部 LLM 输入。

7. CLOB 盘口增强

_market_scout_enrich_quotes() 会遍历每个候选市场的两个 outcome token， 通过 polymarket.get_quote(token_id, outcome) 拉取盘口。

字段 用途
best_bid 当前最高买盘，用于判断市场买卖价差。
best_ask 当前最低卖盘，Paper 自动下注优先用它作为入场价。
bid_size 买盘深度，用于观察盘口厚度。
ask_size 卖盘深度，Paper 模拟成交需要它。
spread Paper 执行前会用它和 max_spread 比较。
updated_at_ms 盘口更新时间，用于页面和日志观察。
容错方式

单个 outcome 盘口请求失败只会在该 outcome 的 quotes 中写入 error，不会让整轮扫描失败。 这能保证扫描器持续运行，但也意味着缺盘口的候选很可能在 Paper 执行闸门里被拦截。

8. LLM 分析

LLM 分析由 _maybe_analyze_market_scout_candidates() 控制。它先做本地闸门，再调用 _call_market_scout_llm()。这个环节只输出判断，不直接下单。

LLM 前置闸门 条件 失败后的日志
市场页 LLM 开关 llm_enabled 必须为 true 写入 LLM 分析未运行，不会下注。
全局 LLM 开关 llm_super_agent_enabled 必须为 true 提示 LLM 配置关闭。
API key POLYBOT2OTHER_LLM_API_KEY 或 HAOAI_API_KEY 必须存在 提示 API key 未配置。
候选签名 TTL 候选签名重复且还在 TTL 内 沿用上一轮 LLM 分析，减少重复请求。

Prompt 约束

  • 身份是严格的 Polymarket 非 BTC 市场分析员。
  • 只允许返回 JSON。
  • 最多选一个市场。
  • 证据陈旧、含糊、接近结算、价差过大、信心不足时优先 NO_TRADE。
  • 当前调用不能浏览网页，必须说明哪些外部新闻需要人工核查。
  • LLM 不负责下单，只输出结构化建议。
LLM 输出字段 含义
decision 只能是 RECOMMEND 或 NO_TRADE。
selected_slug 推荐市场 slug，必须来自本轮候选列表。
outcome 推荐方向，必须和该市场 outcomes 精确匹配。
confidence 0 到 1 的置信度，后端会夹紧。
max_entry_price LLM 认为最多能接受的买入价。
reason 推荐或不交易的理由，最多保留 800 字符。
risk_flags 风险点列表，最多保留 12 条。
news_checks_needed 需要外部新闻核验的事项，最多保留 12 条。
valid_for_seconds 建议有效期，后端夹在 10 到 600 秒。

9. LLM 结果归一化

LLM 原始返回会进入 _normalize_market_scout_llm_decision()。这一步的目标是把模型输出压成后端能信任的结构。

校验项 处理方式
非法 decision 改为 NO_TRADE。
selected_slug 不在候选里 如果原本是 RECOMMEND，会降级为 NO_TRADE。
outcome 不匹配 如果是 RECOMMEND，会降级为 NO_TRADE。
confidence 超范围 夹到 0 到 1，并保留 4 位小数。
max_entry_price 解析为数字，保留 4 位小数，解析失败则为空。
valid_for_seconds 夹到 10 到 600 秒。
risk 和 news 字段 只保留列表前 12 条，并裁剪单条长度。
关键点

LLM 说推荐还不够。只有归一化后仍是 RECOMMEND，并且后续 Paper 闸门全部通过，系统才会尝试模拟下注。

10. Paper 自动下注闸门

_maybe_execute_market_scout_paper_order() 先检查市场页 Paper 自动下注开关。 如果开关关闭，会记录 Paper 自动下注开关关闭，不会继续执行。开关打开后才进入 _build_market_scout_paper_order_result()。

执行闸门 通过条件 拦截原因示例
LLM 决策 decision == RECOMMEND LLM 未给出 RECOMMEND
候选市场 selected_slug 必须在本轮候选里 推荐市场不在本轮候选列表
推荐方向 outcome 必须存在于市场 outcomes 推荐方向不在市场 outcomes 中
最低置信度 LLM confidence 大于等于 min_confidence 置信度 0.xxxx 低于阈值 0.xxxx
入场价 优先用 CLOB best_ask，缺失时使用对应 outcome price 缺少可执行买入价
最高入场价 entry_price <= min(页面最高入场价, LLM最高入场价) 入场价 0.xxxx 高于上限 0.xxxx
最大价差 盘口 spread 小于等于 max_spread 盘口价差 0.xxxx 高于上限 0.xxxx
最大持仓 Market Paper 当前 open trade 数量小于上限 Paper 持仓数已达上限
同市场重复持仓 同一个 slug 不能已有 open trade 该市场已有 Paper 持仓
24h 日亏损 已实现亏损未触达 paper_max_daily_loss Paper 24小时已实现亏损 ... 触达上限
单笔预算 paper_stake_dollars > 0 单笔预算无效
现金余额 Market Paper 隔离账户 cash 大于等于 stake Paper 隔离账户可用资金不足
真钱 Live 当前状态

市场页 live_auto_enabled 在后端被强制锁定为 false。页面显示 Live 锁定和 Live 订单只是状态展示， 当前没有把非 BTC LLM 推荐接到真钱交易接口。

11. 模拟成交和账本写入

Paper 闸门通过后，后端会构造一个二元市场兼容的 MarketRound，再构造 Signal 和 TradeIntent，最后交给 simulate_fak_buy()。

对象 字段策略 说明
MarketRound symbol="MARKET"，round_id=slug 用于和 BTC 账本隔离，同时复用已有 Paper 订单和持仓表结构。
up_token 放入 LLM 选中的 outcome token 这里只是账本兼容映射，不代表方向一定叫 Up。
down_token 放入另一个 outcome token 用于保持二元市场结构完整。
Signal.side 使用原始 outcome 文本，例如 Yes 或 No 下注列表里展示的方向来自这里。
limit_price 使用闸门通过的 entry_price FAK 模拟买入不会用高于限价的价格成交。
taker_fee_rate 来自 settings.paper_taker_fee_rate，默认 0.07 沿用当前 Paper 手续费假设。

写入顺序

  1. market_paper_store.upsert_round(market) 写入或更新市场轮次。
  2. market_paper_store.place_execution_result(intent, execution) 写入 Paper 订单和可能的成交持仓。
  3. 如果 trade_ids 非空，状态视为已提交。
  4. 读取最近一条 MARKET Paper order 作为页面展示的订单 ID。
当前未完成的账本能力

非 BTC 市场当前主要是记录 Paper 买入和持仓。自动结算、按真实市场 resolution 回填输赢、跨市场复盘归因还没有完整接入。 所以 Paper 盈亏在没有结算机制前只能作为下单行为审计，不能当成最终胜率报告。

12. 页面状态和日志

市场页通过独立接口刷新状态、配置和终端日志。用户主要看三块：右上角状态摘要、齿轮配置、Market LLM Terminal。

接口 前端调用 返回内容
GET /api/market-scout-state loadMarketScoutState() 扫描状态、运行配置、Paper 账户、Paper 下注列表、Paper 交易、Live 锁定状态。
GET /api/market-scout-settings 页面初始化时复用 state 返回同一份市场状态，配置在 settings 字段。
POST /api/market-scout-settings saveMarketScoutSettings() 保存齿轮配置，并返回新的市场状态。
GET /api/market-llm-terminal loadMarketLlmTerminal() 增量返回终端日志，支持 limit 和 after_seq。

终端日志模块

scannerstart开始只读扫描非 BTC 活跃市场
scannercomplete扫描 120 个市场，保留候选，展示 20 个，送 LLM 10 个

paperblockedPaper 自动下注未执行，原因写在 message
papersubmittedPaper 自动下注已执行，写入订单 ID 和持仓 ID
settingsupdate市场页控制参数已保存
operatorheartbeat运行心跳，展示扫描、LLM、Paper 和 Live 状态
候选市场

展示扫描后保留的前 20 个候选，包括问题、价格、流动性、24h 成交量、spread、基础分、scout 分和 LLM 标记。

LLM 分析

展示最近一次结构化判断，包括推荐市场、方向、置信度、最高入场价、理由、风险和需核查事项。

下注列表

展示 Market Paper 订单，字段包括时间、市场、方向、状态、限价、预算、成交和原因。

13. 当前策略边界

边界 当前状态 影响
Live 自动下注 锁定 市场页不会触发真钱订单。要接 Live 必须重新设计权限、限额、撤单、签名、订单回执、失败恢复和人工熔断。
外部新闻实时核验 未自动接入 LLM 只能分析传入的市场字段和描述，遇到新闻型市场会要求人工核查。没有实时新闻源时，时效性判断会有硬缺口。
非二元市场 过滤 当前执行链路只处理 2 outcome 市场，多选市场会直接排除。
非 BTC 市场自动结算 未完整接入 Paper 下单和持仓可审计，但不能自动形成最终胜负统计。
胜率保证 无保证 当前系统提供筛选、判断和闸门，不能承诺 80% 胜率。任何策略上线前都需要真实回放、Paper 结算、样本分桶和故障演练。
市场来源 Gamma 和 CLOB 如果 Polymarket API 字段延迟、盘口短暂缺失、市场描述不完整，LLM 判断会受到影响。

14. 压力测试和下一步建议

下面是我对当前链路的压力测试。它能帮助你判断下一步该加什么，避免只盯着“让它多下单”。

如果想更激进

直接降低 min_confidence、提高 max_entry_price、放宽 max_spread 会让订单更多， 同时会显著增加薄盘口、追高和噪音市场暴露。激进参数必须和可结算 Paper 复盘一起上。

如果想更像实盘策略

下一步优先接外部可信新闻源、市场类别白名单、结算回填、LLM 决策归因统计、按类别胜率分桶。 只有这些补齐后，才有资格讨论 Live 自动下注。

建议优先级 改进项 理由
高 接入可信外部新闻和事件源 非 BTC 市场大量依赖实时事件，LLM 只看市场描述会错过最新信息。
高 补齐非 BTC Paper 自动结算 没有结算就无法验证 LLM 推荐质量，也无法统计真实胜率。
高 按市场类别分桶 体育、政治、宏观、加密、娱乐的信号来源完全不同，混在一起看总胜率会误导调参。
中 加入黑名单和白名单 排除长尾、争议性高、难结算、信息源不透明的市场，保留更可解释的类别。
中 记录 LLM prompt、候选快照和盘口快照 方便复盘某一单为什么下注，避免只看到最终亏赢却找不到当时输入。
中 Live 前置人工确认 在 Live 自动化之前，加一个人工确认队列能先观察推荐质量，降低资金暴露。
判断系统有没有工作的方法

先看 Market LLM Terminal 是否持续出现 scanner 心跳和 scan complete，再看过滤统计是否合理， 再看 LLM 是否产生结构化 JSON，最后看 Paper 模块日志是 submitted 还是 blocked。 如果 blocked，message 就是最直接的闸门原因。
